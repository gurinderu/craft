Decide what is "in play" from the diff: payments/amounts/ledger → money; async/threads/locks/transactions → concurrency; input parsing/auth/tenancy → security; loops/queries → performance; always consider errors; new or changed tests, or a changed behaviour no test pins → tests; new branching / growing files / large refactor → maintainability; a changed contract that a party running another version reads, calls or deploys against — stored or wire data, a CLI flag or output, a config key or env var, an API/schema version, an exported name → compat; a changed operation on a domain entity that carries a status/lifecycle field, soft-delete, scoped references, or a documented derived quantity → invariants. ('correctness' and 'intent' are enforced by the engine and added automatically, and so is 'tests' whenever the diff changes production (non-test) source; do not count any of them toward your choices. 'money', 'performance' and 'maintainability' run only when the engine reads their signal in the changed lines itself — picking one neither adds nor keeps it.) Include 'complexity' whenever the diff is medium or large: it runs only when a code-metrics index covers the repository, and is dropped otherwise.
