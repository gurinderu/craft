performance & needless allocation (load the rust-performance skill): allocation in a hot loop (PER-001); `Vec::new()` + push where the size is known — `with_capacity` or collect from a sized iterator (PER-002); N+1 queries / repeated work in a loop (PER-003). And the NEEDLESS-ALLOCATION list — an owned value built where the code only reads it: (a) `collect()` into a Vec only to iterate it once, take its `len()` or call `contains` — iterate the iterator, `.count()`, `.any()` (PER-004); not when the collect ends a borrow before a mutation, the Vec is read twice, or its `len` is taken and then it is iterated; (b) a fn returning `Vec`/`String` that its callers only iterate or read, where `impl Iterator<Item = …>` or a borrow (`&str`, `&[T]`) would do — e.g. a `scopes_vec()` that allocates a Vec of Strings for a caller that walks it once (PER-005); weigh what `impl Iterator` costs: it cannot be returned from a dyn-compatible trait method, before edition 2024 it needs `+ '_` to borrow `self`, and callers lose `len`, indexing and reuse; (c) a parameter typed `&[String]` (or another borrowed collection of owned strings, such as `&[Vec<String>]`) that forces callers holding `&str`s to allocate, where `&[&str]` or `impl IntoIterator<Item = impl AsRef<str>>` serves them (PER-006) — a `&String`/`&Vec<T>` parameter is clippy's `ptr_arg` (the gate seeds it) and an owned `String` parameter is OWN-002: leave those to them; (d) `to_string()`/`to_owned()`/`format!`/`clone()` inside a loop where the value could be borrowed or built once (PER-001) — a clone added only to satisfy the borrow checker is OWN-001, not this; (e) a lookup key built into a `String` (`format!`, `to_string`, concatenation) only to call `get`/`contains_key` (PER-007) — a `String` key is looked up by `&str` directly; a composite `(String, String)` key cannot be looked up by `(&str, &str)` through `Borrow`, so build the key once outside the loop, split into nested maps keyed by `String` and look each level up by `&str`, or look up through `hashbrown`'s `Equivalent` with a borrowed key type that hashes as the owned one does. PUBLIC LIBRARY ITEMS: PER-005 and PER-006 are no finding on a `pub` item of a library crate — changing its return or parameter type is a semver break, which API-006 and the compat lens weigh. SEVERITY: Low, held to the harm caps — a performance cost names no harm row above `none`; say in `why` whether the site is on a hot path (a loop, a request handler, a fn called per item or per request) as information, not as a raise. Not a finding: a one-off allocation at start-up, in a test, in a CLI's argument handling or on an error path; a clone the borrow checker genuinely needs (shared ownership across threads/tasks, a value moved into a closure) — say why it is needless before you file it. ROLL UP (needless-allocation Lows only): instances of one PER pattern go into ONE finding, cited at its first site, whose `why` lists EVERY site as `file:line`, so a re-review can check each; this does not override the sibling sweep (review-rules sweeps.md §1) for defects — a finding that names a harm above `none` is reported at each place.
