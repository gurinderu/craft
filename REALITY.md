# Reality — what a claim is checked against
The realm is the model of the work, the repo is part of its embodiment; this file names the third thing — what the work becomes when it runs, and how to look at it. A claim is settled by its canonical carrier, never by the source that was supposed to produce it; tests are a rung of evidence, not a carrier.

| Claim class | Canonical carrier | How to observe | Who |
|---|---|---|---|
| "the released plugin behaves this way for a consumer" | the installed plugin in a consuming repo | install from the marketplace and exercise it there; falsifier — the skill/agent/workflow is missing from the consumer's session or behaves otherwise | user |
| "the OpenCode plugin's locked production closure has no known high-severity advisory" | `opencode/plugin/package-lock.json`'s production closure as the npm advisory database reads it today | `npm audit --prefix opencode/plugin --omit=dev --audit-level=high`; a later advisory can turn a green commit red, and an unreachable registry fails it too — the carrier is the database, not the commit. Not what a consumer installs: per `opencode/README.md` and `opencode/install.sh` the plugin's dependencies land in the consumer's opencode tree (installed by opencode on startup, or by the consumer adding `@opencode-ai/plugin` and `@opencode-ai/sdk`, unpinned, to their own `package.json`) — that closure is whatever their tree resolves, and this audit does not cover it. Dev tooling (`npm audit` at the root) is reported in CI, not gated | agent |
| "the manifests are valid" | the manifests as the official validator reads them | `npx --yes @anthropic-ai/claude-code plugin validate . --strict` | agent |
| "this skill/agent is well-formed and its `craft:` refs resolve" | the checker's verdict over `skills/`, `agents/`, `workflows/` | `node lib/check-skills.mjs` | agent |
| "this workflow script still parses in the sandbox" | the script compiled inside the sandbox wrapper | `node lib/check-workflows.mjs` | agent |
| "the two deliveries of a review agent reach the same required content" | the requirement keys each side's body reaches, per group of the checker's `REQUIREMENTS` registry | `node lib/check-delivery-parity.mjs` | agent |
| "the helper logic is correct" | the test run — with the fix reverted, the test must fail | `npm test` (`vitest run` over `lib/**/*.test.mjs` and `opencode/**/*.test.mjs`, as `vitest.config.mjs` lists them) — read the raw exit code | agent |
| "the engine does X on a run" (logic inside `workflows/*.js`) | the engine executed in the harness | `runEngine(name, {args, script})` from `lib/engine-harness.mjs` in a test; a string match on the script catches a deletion, not a defect | agent |
| "the code is lint-clean" | ESLint over the linted scope, its type-aware rules on lib/tsconfig.json's and opencode/plugin/tsconfig.json's programs — which need both installs, `npm ci` and `npm ci --prefix opencode/plugin`; without either, loading the config throws naming the missing packages and the command to run (`lib/lint-prerequisites.mjs`), never a silent pass on `any`-typed imports. | "the OpenCode plugin type-checks" | `tsc --noEmit` (`opencode/plugin/tsconfig.json`) over `opencode/plugin/*.ts` and every `opencode/plugin/*.mjs`, tests included, with `checkJs` at the same maximum strictness as `lib/` (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and the rest), JS types from JSDoc — against the plugin's own pinned Node typings (`@types/node` 25.x), not Node 22, so a post-22 API in an OpenCode test is NOT caught here | `npm run check:types` (after `npm ci` and `npm ci --prefix opencode/plugin`: the plugin's tests import `vitest` from the root); falsifier — an unchecked index such as `[1][0].toFixed()` added to an `opencode/plugin/*.test.mjs` fails it | agent |

| "the engines' own code is type-clean" | `node lib/check-workflow-types.mjs`: each `workflows/*.js` wrapped as the sandbox runs it, inlined regions replaced by imports of their lib modules, sandbox globals from `lib/workflow-sandbox.d.ts` (realm #134), `lib/tsconfig.json`'s strictness. `agent()`/`workflow()`/`pipeline()` results are `unknown` (each engine narrows to `T | null`), agent options are the closed `AgentOptions`, `Date.now()`/`Math.random()`/`Date()`/an argless or spread-only `new Date` are refused, through parentheses and `globalThis`, and `Date`/`Math` may otherwise appear only as `Date.x`, `new Date(arg)` or right of `instanceof` (an alias such as `const { now } = Date` is refused); `globalThis` (and `globalThis.globalThis`) may appear only as `globalThis.x` with a literal name; `eval` and `Function` — bare or as a member of `globalThis` (`globalThis.eval`, `new globalThis.Function(…)`, `globalThis['eval']`, through `globalThis.globalThis` too) — a dynamic `import()` and `import.meta` are refused: es2023 declares them and nothing observed shows the sandbox restricts them (realm #134), so they are refused to keep the engines off dynamic code and the host; the engine harness shadows bare `Date` and `Math` with throwing stand-ins under test (a `globalThis` route is refused statically, not shadowed). A JSDoc cast to a type without `any` is where a value takes its type, so the value under it is no site; a JSDoc-typed declaration discharges only the checker's placeholder (an argless `new Map()`), never an `any` a value carries. Code inside inlined regions is checked in its lib module, and every lib module a `craft-inline` fence names is held to zero `any` spelled in its whole source; its implicit `any` is counted where an engine reads it. On the same compiled program (`parserOptions.programs`, ESLint's Node API, `lib/engine-lint.mjs`), typescript-eslint's `no-unsafe-assignment`, `no-unsafe-member-access`, `no-unsafe-call`, `no-unsafe-return` and `no-unsafe-argument` hold each engine's own lines to zero, reported at their `workflows/<file>.js` line, with inline `eslint-disable` ignored; the same program is held to `complexity` 10 and `sonarjs/cognitive-complexity` 15 (`lib/complexity-rules.mjs`), the engine's top-level body — wrapped as the sandbox runs it — counted as one function; a missing ESLint or typescript-eslint fails the check | `npm run check:types:workflows`; falsifiers — `const v = JSON.parse('{}')` then `v.x()` in an engine, even with the ceiling raised to admit the one `any`, fails it with `no-unsafe-assignment` at line 1 and `no-unsafe-call`/`no-unsafe-member-access` at line 2 of `workflows/<file>.js` (planted in `lib/check-workflow-types.test.mjs`), and so does a function or top-level body with ten `if`s (complexity 11) or nested `if`s reaching cognitive 16 (planted there too); further falsifiers — an unchecked index such as `[1][0].toFixed()` added to an engine fails it at that line of `workflows/<file>.js`; so does `effrot: 'low'` in an agent call, `Date.now()` anywhere in an engine (or `const { now } = Date`, `(Date).now()`, `new Date(...[])`, `globalThis.Date.now()`, `const { Date: D } = globalThis`, `globalThis.globalThis.Date.now()`, `eval('1')`, `globalThis.eval('1')`, `new globalThis.Function('return 1')` or `import('node:fs')` in an engine), one more `any` than its ceiling — spelled (`churn: any[]` in review.js's `Plan` typedef, an earlier block of a stacked run) or not (`const m = new Map()`, `/** @type {T[]} */ const a = Array.isArray(x) ? x : []` on an `unknown` x, which the gate lists by line) — or a `/** @type {any} */` added anywhere in an inlined lib module (such as `lib/nested-workflow.mjs`). **A gate attests to form, not to behaviour.** A green suite proves the thing compiles, parses and matches its fixture — never that a function is called with what you think. Close a behavioural claim by executing it with before/after shown: revert the change, watch the test fail, restore it. Logic in a file that cannot be imported (`workflows/*.js`) is extracted into `lib/` so it can be executed.

**Ceiling**:
- "this skill triggers on this prompt" — the triggering evals are a local harness that needs a live model and are excluded from CI (`evals/README.md`); a green CI says nothing about triggering. The ceiling is a local eval run.
- "the review engine produces good findings" — a judgment over someone else's code; no carrier in this repo decides it. Closed only by the owner's reading of a real run's `run-record`.

**The table grows by use.** A session that learned a carrier the table lacks (an unnamed carrier, an observation reachable or not — then under *Ceiling*, a wrong command here) writes the row then, before closing the work that taught it. Only what observation needs goes here; dated measurements and history are realm nodes.
