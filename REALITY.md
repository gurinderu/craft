# Reality — what a claim is checked against
The realm is the model of the work, the repo is part of its embodiment; this file names the third thing — what the work becomes when it runs, and how to look at it. A claim is settled by its canonical carrier, never by the source that was supposed to produce it; tests are a rung of evidence, not a carrier.

| Claim class | Canonical carrier | How to observe | Who |
|---|---|---|---|
| "the released plugin behaves this way for a consumer" | the installed plugin in a consuming repo | install from the marketplace and exercise it there; falsifier — the skill/agent/workflow is missing from the consumer's session or behaves otherwise | user |
| "the OpenCode plugin's locked production closure has no known high-severity advisory" | `opencode/plugin/package-lock.json`'s production closure as the npm advisory database reads it today | `npm audit --prefix opencode/plugin --omit=dev --audit-level=high`; a later advisory can turn a green commit red, and an unreachable registry fails it too — the carrier is the database, not the commit. Not what a consumer installs: Bun resolves the plugin's `package.json` there, direct dependencies pinned, transitive ones floating — that closure is observed only in a consumer's install. Dev tooling (`npm audit` at the root) is reported in CI, not gated | agent |
| "the manifests are valid" | the manifests as the official validator reads them | `npx --yes @anthropic-ai/claude-code plugin validate . --strict` | agent |
| "this skill/agent is well-formed and its `craft:` refs resolve" | the checker's verdict over `skills/`, `agents/`, `workflows/` | `node lib/check-skills.mjs` | agent |
| "this workflow script still parses in the sandbox" | the script compiled inside the sandbox wrapper | `node lib/check-workflows.mjs` | agent |
| "the two deliveries of a review agent reach the same required content" | the requirement keys each side's body reaches, per group of the checker's `REQUIREMENTS` registry | `node lib/check-delivery-parity.mjs` | agent |
| "the helper logic is correct" | the test run — with the fix reverted, the test must fail | `node --test 'lib/**/*.test.mjs' 'opencode/**/*.test.mjs'` | agent |
| "the engine does X on a run" (logic inside `workflows/*.js`) | the engine executed in the harness | `runEngine(name, {args, script})` from `lib/engine-harness.mjs` in a test; a string match on the script catches a deletion, not a defect | agent |
| "the code is lint-clean" | ESLint over the linted scope | `npm run lint` — read the raw exit code, not a wrapper's summary | agent |
| "the OpenCode plugin type-checks" | `tsc --noEmit` (`opencode/plugin/tsconfig.json`) over `opencode/plugin/*.ts` and every `opencode/plugin/*.mjs`, tests included, with `checkJs` at the same maximum strictness as `lib/` (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and the rest), JS types from JSDoc — against the plugin's own pinned Node typings (`@types/node` 25.x), not Node 22, so a post-22 API in an OpenCode test is NOT caught here | `npm run check:types` (after `npm ci --prefix opencode/plugin`); falsifier — an unchecked index such as `[1][0].toFixed()` added to an `opencode/plugin/*.test.mjs` fails it | agent |
| "`lib/` is type-clean" | `tsc --checkJs` at maximum strictness (`lib/tsconfig.json`) over `lib/**/*.mjs`, tests included, plus `opencode/plugin/run-record.mjs` named in its `include` (the OpenCode plugin's other `.mjs`, its tests, are type-checked by `npm run check:types` — row above), types from JSDoc, against Node 22 typings | `npm run check:types:lib`; falsifiers — an injected `git([...], cwd).ok` on the string overload fails it, and so does a post-22 API such as `fs.mkdtempDisposableSync` or a browser global such as `window`, or an unchecked index such as `[1][0].toFixed()` | agent |
| "the engines' own code is type-clean" | `node lib/check-workflow-types.mjs`: each `workflows/*.js` wrapped as the sandbox runs it, inlined regions replaced by imports of their lib modules, sandbox globals from `lib/workflow-sandbox.d.ts` (realm #134), `lib/tsconfig.json`'s strictness. `agent()`/`workflow()`/`pipeline()` results are `unknown` (each engine narrows to `T | null`), agent options are the closed `AgentOptions`, `Date.now()`/`Math.random()`/`Date()`/an argless or spread-only `new Date` are refused, through parentheses and `globalThis`, and `Date`/`Math` may otherwise appear only as `Date.x`, `new Date(arg)` or right of `instanceof` (an alias such as `const { now } = Date` is refused); the engine harness shadows the same reads so they throw under test. Each engine's `any` count is held to `lib/engine-any-ceiling.json`, which can only fall (realm #136): the `any` spelled in its JSDoc (`any`, `*`, `?`, `Function`/`function`, bare `array`/`promise`; every block of a stacked run) plus every value the type checker types `any` in the engine's own lines — an untyped `new Map()` read, an untyped `.catch(e => …)` parameter, a `JSON.parse` result, an implicit `any` an inlined lib export returns — counted where it enters (a local variable at its declaration, not at each read; an evolving `let x = null` at the `any` assigned to it, not at its placeholder declaration). Code inside inlined regions is checked in its lib module, and every lib module a `craft-inline` fence names is held to zero `any` spelled in its whole source; its implicit `any` is counted where an engine reads it | `npm run check:types:workflows`; falsifiers — an unchecked index such as `[1][0].toFixed()` added to an engine fails it at that line of `workflows/<file>.js`; so does `effrot: 'low'` in an agent call, `Date.now()` anywhere in an engine (or `const { now } = Date`, `(Date).now()`, `new Date(...[])`, `globalThis.Date.now()`), one more `any` than its ceiling — spelled (`churn: any[]` in review.js's `Plan` typedef, an earlier block of a stacked run) or not (`const m = new Map(); m.get('x').foo`, which the gate lists by line) — or a `/** @type {any} */` added anywhere in an inlined lib module (such as `lib/nested-workflow.mjs`). Not counted: `any` nested inside a type (`any[]`, `Map<any, any>`) until a value of it is read, and a JSDoc `{Array}`/`{Promise}` without type arguments | agent |
| "engine code uses no global the Workflow sandbox lacks" | the probe workflow on the live Workflow tool — it saw `TextEncoder`, `TextDecoder`, `process` and `require` undefined, `setTimeout`/`clearTimeout` defined (realm @nick/craft, #135; `performance` and `process` on 2026-09-19, `lib/agent-deadline.mjs`); re-run it when the tool changes | proxies: `check:types:workflows` reads engine code with `types: []` plus `lib/workflow-sandbox.d.ts`; `node lib/check-workflows.mjs` compiles each engine as it ships, regions in place, against the same declarations and refuses every name in inlined code that resolves to neither, plus any `require(…)`, `import(…)`, `import.meta`, `eval`, `Function` or `globalThis` there (deliberate reflection such as `.constructor.constructor` is not chased), and fails if its program compiles anything beyond the engines, the ES library and that declaration; `runEngine` shadows `SANDBOX_ABSENT` (`lib/sandbox-globals.mjs`). Falsifier — `new TextEncoder()` or `performance.now()` in an inlined lib function fails check-workflows at its `workflows/<file>.js` line | agent |
| "everything inlined into the engines is strictly type-checked" | `node lib/check-workflows.mjs`, which asks `tsc -p lib/tsconfig.json` for its file list (`--listFilesOnly`) and resolved config (`--showConfig`); needs `npm ci --prefix opencode/plugin` | falsifiers — each makes the checker exit 1 with a FAIL line: a fence naming a test file, a path outside `lib/`, or a file tsc does not read (a dot-file); a strictness flag in `lib/tsconfig.json` turned off; `@ts-nocheck`, `@ts-ignore` or `@ts-expect-error` in an inlined module | agent |
| "the eval corpus is well-formed" | the checker's verdict | `node lib/check-evals.mjs` | agent |
| "trunk actually contains this" | `origin/main` at the forge, never a local ref | `gh api repos/gurinderu/craft/commits/main --jq .sha` | agent |
| "a session hook fires on its event and stays quiet otherwise" | the command stored in `.claude/settings.json`, fed a payload | `jq -r '<path>.command' .claude/settings.json`, then pipe `{tool_input:{command},tool_response:{stdout}}` into `sh -c` with it; falsifier — fires on `echo git push`, or prints invalid JSON. Live: a failing command (`git push --dry-run origin refs/heads/no-such:refs/heads/x`) wakes no PostToolUse hook, a succeeding one does — the filters rely on that | agent |
| "a role agent's own bridge comes up" | the tool list of a launched role subagent, in a session started after the role file landed (the harness reads `.claude/agents/` at session start) | launch the role and have it list its `mcp__iskron-sub-<role>__iskron_*` tools; falsifier — none present. `node ~/.iskron-bridge/iskron-bridge.mjs doctor` from the repo root proves only the entry's form (no `НАДО:` lines), not that a launch gets the tools | agent |
| "a push/merge hook sees the command as run" | the command after user-level rewrites: `rtk hook claude` turns `git …`/`gh …` into `rtk git …`/`rtk gh …` before project hooks see it | `echo '{"tool_name":"Bash","tool_input":{"command":"git push"}}' \| rtk hook claude`; feed the rewritten command to the hook as in the row above (surface pinned in realm `@nick/craft`, #128) | agent |

**A gate attests to form, not to behaviour.** A green suite proves the thing compiles, parses and matches its fixture — never that a function is called with what you think. Close a behavioural claim by executing it with before/after shown: revert the change, watch the test fail, restore it. Logic in a file that cannot be imported (`workflows/*.js`) is extracted into `lib/` so it can be executed.

**Ceiling**:
- "this skill triggers on this prompt" — the triggering evals are a local harness that needs a live model and are excluded from CI (`evals/README.md`); a green CI says nothing about triggering. The ceiling is a local eval run.
- "the review engine produces good findings" — a judgment over someone else's code; no carrier in this repo decides it. Closed only by the owner's reading of a real run's `run-record`.

**The table grows by use.** A session that learned a carrier the table lacks (an unnamed carrier, an observation reachable or not — then under *Ceiling*, a wrong command here) writes the row then, before closing the work that taught it. Only what observation needs goes here; dated measurements and history are realm nodes.
